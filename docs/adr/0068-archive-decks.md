# 68. Archive a deck

- Status: Accepted
- Date: 2026-11-02
- Refers to: SPEC §3, §4.1, §4.6, §4.7; `docs/briefs/phase-3a.md` (slice 4); ADR 0035 (`suspended` kept by an import), ADR 0066 (Merge Into…), ADR 0067 (an import keeps a card's own deck), ADR 0058 (toasts at 360 px), ADR 0012 (Delete Deck and its undo)

## Context

A deck the user is done with for now (last term's course, a finished language trip) clutters the deck list and keeps adding to the day's study, but deleting it loses nothing the user wants to lose: its cards and their history should stay, searchable and exported, ready to come back. The brief asks for "Archive" in a deck's ⋮ menu with an Undo toast; an archived deck leaves the deck list, the study counts, the global statistics' forecast and retention, and the remembered "last deck"; its cards stay in All Cards, behind a filter hidden by default, and in exports; an "Archived Decks" row at the end of the deck list opens a page with Unarchive. It pre-approves migration 0012 (a nullable `decks.archived_at`) and an optional `archived_at` on the export's deck records, the format number staying 2 as for `suspended`.

## Decision

**Schema.** Migration 0012 adds `decks.archived_at INTEGER` (UTC milliseconds), NULL for every existing deck. An archived deck is **live**: `deleted_at` stays NULL, so its name stays taken (the live-name unique index is untouched), its cards stay live, and every rule about deleted rows is as before. Archiving is a flag, not a state of the cards: no card row changes, and nothing in the log is written, so archiving is never part of the history FSRS learns from.

**Core** (`storage/decks.rs`):
- `archive_deck(id)` stamps `archived_at` with the current time, in one transaction, and **does not change `updated_at`** (which records renames): an export made before archiving still finds the deck identical but for the flag, which an import ignores (below). Archiving a deck that is already archived is refused with `Error::DeckArchived` and keeps the first stamp: a stale menu or a second window can never make an Undo unarchive a deck archived earlier. A missing or deleted deck is `DeckNotFound`.
- `unarchive_deck(id)` clears it; on a deck that is not archived it changes nothing (it is the Undo, and lenient like the other Undo calls, ADR 0035). Archive then Unarchive leaves the database exactly as it was (`test_support::dump`, tested).
- `list_decks` and `decks` return the live decks that are **not** archived; `decks_with_archived` returns every live deck, each with its `archived_at` (`Deck` gained the field and `is_archived`), for what names any live deck: the name check, All Cards' deck filter and import conflicts. `archived_decks` lists the archived ones with their live card counts, sorted like the deck list, in one query. `deck(id)` returns a live deck archived or not.
- **Left out when archived:** the deck list and so its counts; a study session (`study_input` refuses an archived deck with `DeckArchived`, so a session cannot start on one); the **global** statistics' forecast, overdue count, scheduled count and expected retention (`Scope::All` reads only schedules of decks that are not archived); merge targets (`merge_deck` refuses an archived target with `DeckArchived`: its cards would leave study unseen).
- **Kept:** All Cards (`BrowseQuery::include_archived`, false by default; `browse_row` returns a card's row whatever the filter); exports; the **global activity** (reviews per day, time, pass rate), which is history: the reviews happened whether or not the deck is studied now; a deck's own statistics (`Scope::Deck` of an archived deck is whole; the app does not offer them, since an archived deck has no page); the tags in use (suggestions and All Cards' tag filter); `card_count`, `list_cards`, card edits, moves out of the deck and their Undo, which may move cards back into it.
- **Names.** A name an archived deck has stays taken. Creating, renaming or undeleting to it fails with a distinct `Error::ArchivedDeckName` (found inside the failed write's transaction, `name_taken`), so the message can say the deck is archived; the app's name dialog says so before the store is asked ("An archived deck is named “Spanish”").
- **Other deck operations.** Delete Deck of an archived deck works in core and Undo brings it back archived; Merge Into… of an archived source works in core, and its Undo brings it back archived. The app offers neither: an archived deck has no row in the deck list and no page.

**The export** (format version 2, unchanged number, as for `suspended` in ADR 0035): every deck record has `archived_at` after `updated_at`, `null` when the deck is not archived. A file without it reads as not archived, so every file made so far imports. The field reads **any** JSON value (`format::ArchivedAt`), so a value of another type is refused as this field of its row with a `FieldProblem` rather than as malformed JSON: a string, a fraction (even `1.0`), a boolean, an array or an object is `NotATimestamp` (new); a negative number, one past the year 9999 or one too large for 64 bits is `TimestampOutOfRange`, as for every timestamp. An array or object is skipped value by value, never kept, under the reader's own bounds on strings and nesting (ADR 0053).

**The import** mirrors `suspended`: an import never changes how a live deck is studied.
- A **new** deck keeps the file's flag.
- A deck the database has that differs **only in `archived_at`** is already present, whichever way either side has it, and the database keeps its own flag. A deck revived by the import (deleted here, live in the file) keeps the database's flag too. With ADR 0067 this means an import never reorganises: not where a card is, not whether a deck is studied.
- A live deck name in the file that an archived deck has here is a conflict, as for any live deck.
- The import's independent model (`interchange/tests/oracle.rs`) has the rule, written apart from the engine, and the random histories of the property tests archive and unarchive decks (`Op::Archive`, `Op::Unarchive`, also among the reorganisations of `an_older_export_imports_after_a_reorganisation`, which now also asserts that every live deck keeps its flag). Dropping the rule from the engine fails both randomised tests (checked by mutation).
- **The Anki import never archives.** Its new decks are not archived; an Anki deck whose name an archived deck has goes into that deck (the existing rule for a live deck of the same name), which stays archived.

**UI.**
- **Archive** in each deck row's ⋮ menu (Rename…, Merge Into…, Archive, Delete: not destructive, so above Delete) and in the deck page's Deck Menu, in the section with Merge Into… (that menu has no Delete). It archives at once; the toast "Deck archived" offers Undo (Unarchive). On the deck list the row leaves and the focus goes to the row now at its place, else the last one, else Create Deck (`index_after_removal`). From the deck page, the page goes back to the deck list with the focus on the row now at the deck's place (`RappelWindow::leave_archived_deck`; the toast is shown from the deck list, which lives as long as the window). Undo has every page read its decks again and focuses the deck's row if the list shows.
- **"Archived Decks"** at the end of the deck list: an `AdwActionRow` with the count and a chevron, in a boxed list of its own under the decks (apart from them, as it is not a deck), shown only while a deck is archived; the screen reader hears "Archived Decks, 2 decks". When every deck is archived the list's empty state says "Every Deck Is Archived" ("Create a deck, or unarchive one to study it again"), keeps Create Deck, and shows the same row under it.
- **The Archived Decks page** lists each archived deck (name as plain text, two lines at most, and its card count) with an **Unarchive** button whose tooltip and accessible label name the deck ("Unarchive “Spanish”"). The focus goes to the first button in `shown`. Unarchive brings the deck back at once with the toast "Deck unarchived" and Undo (Archive again); the focus moves to the row now at its place. **After the last one, the page goes back to the deck list with the focus on that deck** rather than showing an empty page: the list is where the deck now is, and an empty page would only say there is nothing here. (The page still has an empty state, "No Archived Decks", for the case where the last archived deck goes while it is open, from another window or an Undo.)
- **All Cards** gets a fourth drop-down, "Archived Hidden" / "Archived Shown" (tooltip and accessible label "Archived Decks"), in the same style as the others and **shown only while some deck is archived**: with none, it would offer a choice that changes nothing. Hidden is the default each time the page opens. Shown, the deck filter lists the archived decks too, marked "Spanish (archived)" (the name isolated, so a right-to-left name cannot reorder the mark); hidden, it lists the others and drops an archived choice back to All Decks. **It is a view setting, not a filter**: Escape and Clear Filters leave it as it is, and it does not make "Clear Search" read "Clear Search and Filters"; otherwise Escape on a freshly opened All Cards would reveal the archived cards instead of going back. When every card is in an archived deck and they are hidden, the page says "Only Archived Cards" ("The cards of archived decks are hidden") with a **Show Archived Decks** button, rather than "No Cards Yet". Move… and Move to Deck… never offer an archived deck (`move_card::targets`), nor does Merge Into… (`merge_deck::targets`, the one place for both menus).
- **Window state.** A saved "last deck" that is archived leaves the deck list showing at startup, as a deleted one does (`DecksPage::open` ignores an archived deck).
- **Statistics.** The global page's forecast and retention follow core; no line was added to say archived decks are left out. The deck list, which is what the forecast predicts, does not show them either, so the two agree without explanation, and every line added to that page is one more for a screen reader.

## Consequences

- Migration 0012 is the only schema change; the export keeps format version 2. A 0.3.0 build refuses a file that has `archived_at` (its `deny_unknown_fields`), the cost already accepted for `suspended` (ADR 0035; nothing is stable before 1.0).
- Machines that share exports archive independently: archiving on A does not archive on B when A's export is imported there, and the other way round. The plan says nothing about it, since nothing would be written.
- A user who archives every deck still sees Create Deck and the way back to them, and All Cards says why it lists nothing.
- The deck page has no Unarchive: an archived deck has no page. Unarchive is on the Archived Decks page only.
- An archived deck's own statistics are not reachable from the UI; core keeps them whole for when it is unarchived.
