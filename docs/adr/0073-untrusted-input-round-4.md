# 73. Untrusted input, round 4: the paths of phase 3a; clean-up #4

- Status: Accepted
- Date: 2026-11-03
- Amends: ADR 0063 (rows 74 on of the untrusted-input table), ADR 0070 (the `query_only` guard puts back what it found), ADR 0072 (the lookup sorts its matches in Rust; All Cards' search knows private-use characters too), ADR 0058 (a toast's title never ends inside a name), ADR 0024 (a failing GTK test says what failed)
- Refers to: SPEC §4.10, §4.1, §4.5, §4.6; `docs/briefs/phase-3a.md` (slice 8); ADR 0049 (time bounds), ADR 0065 to 0072

## Context

Phase 3a added new ways in and new bulk work: the import's `archived_at` and its rule that an import keeps a card's deck (ADR 0067, 0068), merging decks and its Undo (ADR 0066), archiving (ADR 0068), sessions over a tag (ADR 0069), practice that writes nothing (ADR 0070), the export that leaves its media out (ADR 0071), the editor's same-front lookup (ADR 0072), and selection mode on the deck page (ADR 0065). Rounds 1 to 3 (ADR 0025, 0050, 0063) kept one table per round; this is round 4, numbered on from row 73. Earlier slices also handed this one follow-ups from their reviews.

## Decision

### Method

As ADR 0050 and 0063: each attack is a test; one that passes at once means the defence already held, and says so. Every fix was checked against the code without it: the deck page's flags (row 81) ran on the old code in the working tree and took 234.6 s of CPU against 0.17 s; the nested `query_only` (row 78) panics inside the outer read without the fix; the private-use search (row 86) builds the query "abc" without it; the streaming test (below) failed with the import's guard removed in a scratch copy under `target/scratch-s8`. The killed practice (row 77) was checked to see a write: an answer written by the child process fails it. Time bounds are CPU time at the reference machine's speed (ADR 0049), about ten times the measured value, in a debug build.

### Follow-ups from earlier reviews

- **Selection mode cost O(n) per list change** (slice 2's review). `ui::selection` walked the whole list on every `items-changed` (to drop cards that left) and on every `update` (to read the chosen items), even with nothing chosen; the deck page's `refresh_new_flags` spliced each changed row separately, and each splice also re-read the study counts. Now nothing is walked while nothing is chosen, and the flags change in one splice over the range of changed rows (`changed_range`, pure; unchanged rows go back as the same items). At 10,000 cards with every flag changed and one card chosen: 234.6 s of CPU before, 169 ms now (`ctrl_a_on_ten_thousand_cards_is_quick_and_its_bulk_action_undoes`, bound 2 s).
- **The test binary's SIGSEGV** was found and fixed in slice 4 (ADR 0024, amended: the tests ran on the desktop's Wayland and input method). Checked that it holds: the whole app test binary ran 6 times in a row beside 20 busy loops on the 20-thread machine; no run died of a signal (see the PR for each exit).
- **The streaming comparison missed a guard** (slice 3's review). `streaming_gives_what_reading_the_whole_document_gave` now draws its later writes mostly from the reorganisations (`property::reorganisation`: moves, merges, deck deletes, archives), so "moved since, deleted with its new deck, live in the file" is common. With the guard of `classify_card` removed, it fails within its 160 cases (it did not before). `an_older_export_imports_after_a_reorganisation` uses `prop_assume!` instead of returning early on a conflict, so the cases it counts are cases it checked.
- **A toast's title cut inside a name** (pre-existing). A long toast showed its first clause as its title; "“Spanish: verbs” could not be restored: …" showed "“Spanish" and put "Verbs” could not be restored…" behind Details. Now a text whose name comes first is built by `ui::toast::Message::from_template`, which finds the clause end in the translated template before any name is filled in (Delete Deck's and Merge Into…'s failed Undo), and `toast_text` never ends a title between “ and ” or « and » for any other text.
- **All Cards' search and private-use characters** (slice 7b's review). The search trimmed what came before a word's first letter or digit, so "\u{E000}abc" was searched as "abc", which no token is (unicode61 keeps `Co` characters in tokens). `storage::search::starts_token` (letter, digit or private-use character) is now the one rule of where a word starts, shared with the same-front lookup.
- **The flaky drop-down test** (`ui::dropdown::tests::the_factories_survive_new_labels_and_the_popup_stays_narrow`). It failed in full gate runs in #108 and #113 and never alone, each time "with no panic message". The message was lost by the harness, not by the test: a body runs on the main-context thread, whose output goes to the capture of the test that started the thread (long finished), and `resume_unwind` on the test's thread calls no hook. Now `testing::on_main_context` keeps the panic's place and message and panics with them on the test's own thread, so a failing GTK test always says what failed and where (`a_failure_on_the_main_context_says_what_and_where`). Every failure was before slice 4's fix, while the tests ran on the desktop's compositor; since then it has not failed: 40 runs of the drop-down tests and 6 of the whole binary under load passed it. Its waits are for GTK (the window and the popover mapped), not time bounds, and are kept. If it fails again, the output now names the assertion. Other tests that were flaky in phase 3a's PRs: `pages::deck_page::tests::after_a_bulk_removal_the_focus_follows_the_list` (2 in 21 runs, #115, fixed there by waiting for the focus); none else was reported.

### Clean-up #4

- **Shared:** the deck targets of Merge Into… are Move to Deck…'s (`merge_deck::targets` calls `move_card::targets`); the test helpers that walk widgets, count rows, read labels and settle the main context are `testing::descendants`, `label_texts` and `settle` (four copies gone); the review page's menu check uses `testing::menu_item_sensitive`; `test_support::learn` and `tag_id` (two copies each). Many cards for a GTK test are written in one transaction by `testing::state_with_many_cards` (adding 5,000 one by one waits for the disk at each and took most of a minute).
- **Narrowed:** in core, `front_key`, `export_size_at_least`, `MAX_ARCHIVE_BYTES`, `PRACTICE_LIMIT` and the fields of `Merged` were `pub` and used by no front end: now `pub(crate)` (ARCHITECTURE.md's rule). In the app, test-only accessors are `#[cfg(test)]` (`SelectionHeader::title`, `select_all_button`, `SelectionBar::is_revealed`), and helpers used inside their module are private (`select_all::is_key`, `merge_deck::prepare`, `choose_target`).
- **Left, and why:** `next_study_change_in` and `tag_next_study_change_in` hold the same query with another `FROM`; joining them would touch the deck path that ADR 0069 kept unchanged and pinned by its tests. Files over 800 lines stay, as ADR 0063 said. Pages' one-line `error_toast` wrappers stay: each names what failed for the log.

## Consequences

- Nothing the user sees changes but two fixes: an error toast about a deck whose name has ":" now shows its whole text behind Details instead of a cut name, and All Cards finds a word that starts with a private-use character.
- A failing GTK test now prints its message and place.
- The gate grows by about the time of the new scale tests (the 10,000-card pages, the 20,000-card merge, the hostile fronts: under 20 s together in a debug build).
